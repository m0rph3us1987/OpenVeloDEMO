# Implementation Plan: Job 2 — Persistent Left Sidebar Layout (focus-visible + responsive wrap-up)

## 1. Goal & Scope

Job 1's base layout already exists. This plan adds the two concrete extras called out by the user:

1. **Explicit, readable `focus-visible` states** on every sidebar `NavLink` and on the `Button` primitive (replacing the current `focus-visible:outline-none`).
2. **Responsive sidebar/content behavior** in `Layout.tsx` so the sidebar stays always-visible, never shrinks/collapses, uses a viewport-appropriate width, and the main pane uses `min-w-0` + safe overflow.

Constraints: stays inside the existing Tailwind class-based dark mode (no new dependencies), preserves the existing route table (`/`, `/recipes`, `/ingredients`, `/shopping-cart`), keeps the `useThemeStore` toggle contract, and produces visible diffs against `origin/staging`.

## 2. Architectural Reconnaissance

- **Codebase style:** React 18 + TypeScript + Vite, Tailwind CSS, `class-variance-authority` for the `Button`, `clsx` + `tailwind-merge` via the `cn` helper in `apps/web/src/lib/utils.ts`.
- **Dark mode strategy:** `darkMode: 'class'` in `apps/web/tailwind.config.ts`; `dark` class is toggled on `<html>` by `useThemeStore` in `apps/web/src/store/theme.ts`. Colors come from CSS variables in `apps/web/src/index.css` (`--background`, `--foreground`, `--muted`, `--accent`).
- **Layout shape:** `apps/web/src/components/Layout.tsx` renders `<div class="flex h-full"> <aside …> <main class="flex-1 p-6 overflow-auto">`. Root route layout — sidebar never remounts.
- **Button primitive:** `apps/web/src/components/ui/button.tsx` uses `cva` with variants `default | outline | ghost`. The base class currently includes `focus-visible:outline-none` and **no replacement ring**, so keyboard focus is invisible — this is the explicit accessibility gap to close.
- **NavLinks:** `Layout.tsx` lines 22–38 define `className` via `cn()` with `bg-accent text-background` (active) and `hover:bg-muted` (inactive). No `focus-visible` ring.
- **Tokens already available:** `background`, `foreground`, `muted`, `accent`. No `ring` / `primary` colors exist yet — needed for focus ring contrast.
- **Tests:** Vitest + jsdom. Existing test at `apps/web/tests/theme.test.ts` shows the mocking pattern (stub `matchMedia`, reset `localStorage` and `document.documentElement.className` in `beforeEach`). `npm test` from the repo root runs all workspace tests.
- **Build/test commands:** `npm run typecheck`, `npm test`, `npm run build` (root). `setup.sh` already runs `npm ci`.

## 4. Proposed Changes

### 4.1 Theme ring tokens (`apps/web/src/index.css`)

Add a new HSL token `--ring` to both color blocks. Pick a brand-consistent color that has AA contrast on both `--background` tokens:

- `:root` `--ring: 222 89% 55%` (saturated blue, ~AA on white). Add `border-color: hsl(var(--ring))` reuse via `border-input` is unnecessary; the variable is for `ring` only.
- `.dark` `--ring: 217 91% 60%` (lighter blue, ~AA on near-black).

Keep all existing tokens unchanged.

### 4.2 Tailwind `ring` color (`apps/web/tailwind.config.ts`)

Under `theme.extend.colors`, add:

```
ring: 'hsl(var(--ring))',
```

This makes `focus-visible:ring-2 focus-visible:ring-ring` resolve.

### 4.3 Button primitive (`apps/web/src/components/ui/button.tsx`)

Replace the substring `focus-visible:outline-none` in the `cva` base string with:

```
focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background
```

Rationale:
- `ring-2` + `ring-ring` is visible in both themes via the `--ring` token.
- `ring-offset-2` + `ring-offset-background` separates the ring from the button's own background (and from the dark sidebar surface).
- `outline-none` is kept to avoid the default browser outline doubling up; the ring is the visible focus indicator.

### 4.4 Layout (`apps/web/src/components/Layout.tsx`, lines 18–44)

- Outer wrapper: keep `flex h-full`. Add `min-h-0` so the container can scroll its children safely.
- `<aside>`: change `w-60` to responsive widths `w-56 md:w-60 lg:w-64`, add `shrink-0` (sidebar must never shrink), keep `border-r border-muted p-4 flex flex-col gap-2`. Optional: `h-full overflow-y-auto` so the sidebar handles tall viewports.
- Each `NavLink` `className`: add `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background` to the `cn()` base. Order of classes is irrelevant thanks to `tailwind-merge`.
- `<main>`: replace `flex-1 p-6 overflow-auto` with `flex-1 min-w-0 p-4 md:p-6 overflow-auto`. `min-w-0` lets long content (tables, code) shrink and let the scrollbar appear instead of overflowing the flex child.

### 4.5 Tests (`apps/web/tests/layout.test.tsx`)

Three minimal, focused tests, all running in jsdom via the existing vitest config:

1. **Renders all four nav entries inside the sidebar.** Render `<Layout />` inside `<MemoryRouter initialEntries={['/']}>`. Assert the sidebar contains `Dashboard`, `Recipes`, `Ingredients`, `Shopping Cart`. Use `@testing-library/react`'s `screen.getByRole('link', { name: ... })` for each.
2. **Active route has accent styles.** Render at `/recipes`. Assert the `Recipes` link's className includes `bg-accent` and the `Dashboard` link does not.
3. **Focus-visible ring present.** In the same render, assert any `NavLink`'s className contains `focus-visible:ring-2` and the toggle button's className contains `focus-visible:ring-2`.

Mocking: none beyond the wrappers above. The layout doesn't touch `matchMedia` or external endpoints. The theme store is read via `useThemeStore`; do NOT mock it — call `useThemeStore.setState({ theme: 'light' })` in a `beforeEach` to keep the test deterministic. Do not assert colors/visuals (no jsdom color queries).

### 4.6 No new dependencies

`@testing-library/react` is already in `apps/web/package.json` devDependencies. No `setup.sh` changes required.
